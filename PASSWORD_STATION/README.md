# Password Station

Self-service passwords for several Active Directory domains, such as the GMP domain and the business
domain (which Entra Connect syncs to Entra ID / Microsoft 365):

| Function | How the user proves who they are |
|----------|----------------------------------|
| **Change my password** (also when it has expired) | current password |
| **Set up recovery details** | current password, then a code sent to the new e-mail / mobile number |
| **I forgot my password** | 6-digit code sent to their registered personal e-mail or mobile |
| **Unlock my account** | 6-digit code sent to their registered personal e-mail or mobile |

There is no help-desk-assisted reset. Admins can only remove a user's recovery details (lost phone),
after which the user signs in and registers new ones.

## Safety rules built in

- **Privileged accounts are never self-service:** `adminCount=1`, Domain / Enterprise / Schema Admins,
  Administrators, Account / Server / Backup / Print Operators, and any extra groups you list for a domain.
  Disabled accounts are refused too. Optionally, only members of one group (nested) are allowed.
- **No account enumeration:** "forgot" and "unlock" give the same answer whether or not the user exists,
  is enrolled, or typed the right recovery address. A code is sent only when all three match.
- Codes expire after 10 minutes, allow 5 tries, and are stored only as HMACs. 5 code sends per account
  per hour, 30 requests per IP per hour.
- Recovery e-mails / phone numbers and the directory service-account passwords are encrypted with
  AES-256-GCM (`PS_DATA_KEY`). The user's work address gets a notice after every change, reset,
  unlock or new recovery detail.
- Every action goes to a hash-chained audit log (Admin → download CSV; the console checks the chain).
- Password rules are enforced by the domain itself (complexity, history, minimum age); Password
  Station adds a minimum length and "not your user name" check and shows AD's refusal plainly.

## Connecting a real AD domain

1. **Network:** the server must reach a domain controller on **TCP 636 (LDAPS)**. On AWS that means a
   site-to-site VPN (or Direct Connect) from the VPC to the GMP / business networks. LDAPS needs a
   certificate on each DC (AD CS "Domain Controller" / "Kerberos Authentication" template is fine).
2. **Service account** in each domain, e.g. `svc-pwstation`, a normal user (not an admin) with a long
   random password that never expires. On the OUs that hold the users (not on admin OUs), delegate:
   - *Reset password* (extended right), and
   - *Read/Write* `lockoutTime` (to unlock).
   AD Users and Computers → OU → *Delegate Control* → custom task → User objects → those permissions.
3. **Admin console** (`/admin/login`, user `admin`, password `PS_ADMIN_PASSWORD`) → **Add domain**:
   - Key `gmp`, name shown to users e.g. "GMP domain"
   - Domain controllers: `dc1.gmp.local, dc2.gmp.local` (tried in order), port 636
   - Base DN: `DC=gmp,DC=local`; users sign in with `sAMAccountName` or `userPrincipalName`
   - Service account (UPN or DN) and password
   - Your internal CA certificate (PEM) if the DCs' certificates come from your own CA
   - Optional: allowed group, extra protected groups (e.g. your tier-0 / GMP system admin groups)
   - **Save & test connection**
4. Repeat for the business domain, named e.g. "Business (Microsoft 365)". A password set there reaches
   Entra ID through Entra Connect password hash sync (~2 minutes). If you use pass-through
   authentication instead, it applies at once.
5. Turn demo mode off (`PS_DEMO=false`) and configure e-mail and/or SMS (below).

Change of an expired password works because the change request is sent over the service account's
connection (AD still checks the old password and history); the user can't bind with an expired
password themselves.

## Settings (environment)

| Variable | Meaning |
|----------|---------|
| `PS_SECRET_KEY` | signs sessions and code hashes (required, keep stable) |
| `PS_DATA_KEY` | base64 of 32 random bytes; encrypts recovery details and bind passwords (required, **never change** after users enrol) |
| `PS_ADMIN_PASSWORD` | first password of the `admin` console account |
| `PS_BASE_URL` | public address, e.g. `https://passwords.abelzeta.com` |
| `PS_SUPPORT_CONTACT` | shown to users who need help |
| `PS_SMTP_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_FROM` / `_STARTTLS` | e-mail for codes and notices |
| `PS_SMS_PROVIDER=sns`, `PS_SMS_SENDER_ID`, `AWS_REGION` + AWS credentials | SMS codes via Amazon SNS |
| `PS_DEMO`, `PS_DEMO_OUTBOX` | trial only: built-in test domains; codes stored in Admin → Outbox instead of sent |
| `PS_CODE_TTL_MINUTES`, `PS_CODE_MAX_ATTEMPTS`, `PS_SENDS_PER_ACCOUNT_HOUR`, `PS_REQUESTS_PER_IP_HOUR` | limits |

In the AWS portal deployment these are generated by `deploy/configure.py`; see `deploy/README.md`.

## Demo mode

Two test domains ("GMP domain (demo)" and "Business - Entra ID / Microsoft 365 (demo)") with users
`jdoe`, `asmith` and the protected `da-admin`, all with password `Welcome-Demo-2026`. Five wrong
passwords lock a demo account, so the unlock flow can be tried.

## Run locally / tests

```bash
pip install -r requirements.txt
PS_SECRET_KEY=dev-secret-dev-secret PS_DATA_KEY=$(python -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())") \
PS_ADMIN_PASSWORD=Admin-Pass-2026x PS_DEMO=true PS_DEMO_OUTBOX=true python run.py      # http://localhost:8200
python -m pytest -q
```

The AD connector is tested against ldap3's offline mock AD (`tests/test_ad.py`).

Admin locked out (5 wrong passwords lock it for 15 minutes)?
`docker compose exec passwordstation python reset_admin.py [--password ...]`
